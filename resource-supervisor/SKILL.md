# 资源监制

把剧本内容与创作风格转成可追溯、可复用、视觉一致的人物、物料和场景资产。先完成全局分析和提示词，再生成图片；不要边读边出图。

## 输入处理

1. 读取用户上传的全部剧本、分集梗概、人物小传、分镜、风格文档和参考图。按文件类型调用相应文档、PDF、图片或表格能力；不得仅凭文件名推断内容。
2. 将创作风格整理为一份全局视觉圣经，至少覆盖：时代与地域、类型与情绪、媒介或写实程度、色彩、光线、镜头语言、材质、服化道、禁用元素。
3. 若用户只给出剧本而未给风格，依据剧情提出一套明确且克制的默认风格，并标注为推断。若缺失内容会根本改变时代、角色身份或交付范围，才询问用户；其余情况用合理假设继续。
4. 剧本较长时按场次或集数建立索引，再汇总全剧。记录每个元素首次出现及关键出现位置，避免漏项和重复项。

## 建立元素清单

分三类提取并归一化名称：

- 人物：有视觉意义的主要人物、配角、群体角色及必要的年龄或时间阶段。替身、伪装、伤后状态、年龄跨度或服装显著变化仅在画面差异足够大时拆为变体。
- 物料：推动剧情、反复出现或需要专门设计的道具、武器、载具、文件、饰品、装置、标志物和特殊陈设。忽略无叙事价值的通用杂物。
- 场景：独立拍摄空间及其有显著视觉变化的时间、天气、年代、破坏或布置状态。相同地点的小幅变化合并为变体。

对别名、称谓和同一地点的不同写法去重。每项必须有：唯一 ID、标准中文名、类别、剧情证据、叙事功能、外观要点、连续性约束、出现位置、优先级。不得把剧本未支持的关键身份、品牌、纹样或历史细节写成事实；必要补全须标注“视觉推断”。

先向用户展示简短统计与高优先级清单，再继续制作完整提示词。除非用户明确要求审批，不要停下来等待确认。

## 分析人物换装与服装连续性

完成场次索引后，为每个有跨场出现的人物建立“人物 × 场次 × 装造”连续性表。至少记录：人物 ID、装造变体 ID、适用集数/场次、剧情阶段、服装层次、鞋履、配饰、发型与妆容、磨损或伤后状态、换装触发原因、与基础定妆共享的身份锚点。

按以下规则决定是否新增装造变体：

- 剧本明确写出换衣、制服、礼服、睡衣、伪装、伤后包扎或时间跨度时，必须拆分。
- 场合、身份或处境显著改变且原服装不合理时，例如工作、居家、街头落难、正式商务、宴会、婚礼、葬礼、恶劣天气，允许依据剧情新增变体并标注“视觉推断”。
- 同一服装只有外套开合、轻微污渍或单件配饰变化时，默认记为同一变体的状态，不重复出图；只有轮廓、材质、色彩层次或叙事身份明显改变时才新增。
- 不要机械地为每个场景创建一套服装。每个变体必须能指出换装触发场次和后续复用范围。
- 变体命名使用 `CHR-001-A 基础装造`、`CHR-001-B 场景装造`；文件名使用 `CHR-001_人物名_装造名`，保持同一人物资源族可排序。

若已有合格基础定妆图，必须把它作为换装图的身份参考，通过身份保持式图像编辑生成新装造，不得从零独立重画。换装时锁定脸型、五官、年龄、肤色、体型、身高比例及剧本未要求改变的发型；只改变服装、鞋履、配饰、必要妆容和剧情状态。若换装剧情同时要求发型或妆容改变，明确列出允许变化项，其余身份锚点仍须保持。

每套新增装造仍单独生成完整白底 16:9 四视图设定板。左上角中文标注采用“人物名·装造名”，以便与基础定妆区分。

## 撰写剧情化提示词

先读取 [references/output-spec.md](references/output-spec.md)，严格使用其中字段和模板。

每条提示词必须同时包含：

1. 元素身份与可见特征；
2. 与具体剧情、人物关系或关键行动直接相关的细节；
3. 全局创作风格；
4. 构图、视角、镜头、光线、色彩与材质；
5. 连续性锚点，即后续图片中必须保持不变的特征；
6. 负面约束，排除时代错置、额外人物或肢体、错误文字、水印、拼贴混乱及不符合剧情的装饰。

使用视觉可观察的语言，不用“高级感”“有故事感”等空泛词替代画面描述。提示词中的每个剧情化细节都应能回指剧本或明确标注的视觉推断。

## 人物设定图硬性规范

每个人物或人物变体生成一张独立设定图，以下要求不可被风格参考覆盖：

- 画布为横向 16:9，推荐交付尺寸 1600×900 或更高的等比例尺寸；纯白背景，正交式角色设定板，光线中性、无环境场景。
- 左侧占画布约 40%，只展示一张正面头肩细节图。人物脸部必须清晰并显著大于右侧全身视图；完整保留头顶，下边缘裁至锁骨附近，只露出少量肩部和服装领口，不得延伸到胸部或腰部。
- 右侧占画布约 60%，平均分为三个等宽区域，从左到右展示同一人物、同一服装、同一比例的正面全身、严格 90 度侧面全身、完全背面全身。三个人物必须等高、等宽、基线一致，并完整露出头顶与脚底。
- 左上角只用中文清晰标注人物名称；除该名称外不得出现标题、英文、参数、水印或其他文字。
- 四个视图必须保持脸型、五官、发型、年龄、肤色、身材、服装、配饰和伤痕一致。侧面必须为严格 90 度，背面必须完全背向镜头。
- 同一人物的不同装造之间必须保持身份一致；将基础定妆与换装图并排检查脸型、五官、年龄、肤色、体型和身高比例。换装图内部的四个视图必须使用同一套新服装，不得混入基础服装部件。
- 左侧头肩特写用于确认面部纹理和身份；右侧三视图用于确认轮廓、服装结构和比例，不得使用夸张透视或遮挡。

若图像模型未准确渲染中文名、16:9 画幅、锁骨裁切、四视图布局或人物一致性，保留满足要求的特征并重新生成。若整体画幅略有偏差，允许在不重绘内容的前提下确定性裁切为 1600×900。不得把明显不合格图片作为最终交付。

## 物料与场景图

- 物料：默认使用 4:3 清洁设定板，主体独立、完整可见，包含最能说明结构的主视角与必要细节；保持剧情中的磨损、年代、材质、机关和使用痕迹。只有剧情需要时才加入持有者或使用情境。
- 场景：必须使用横向 16:9 的 2×2 四宫格四方位场景设定板。整个画布平均分成四格，每格自身均为严格 16:9，排列固定为：左上“总览图”、右上“总览图反向”、左下“左侧面视角”、右下“右侧面视角”。四格必须描绘同一个空间和同一剧情状态，不得生成四个不同地点，也不得以低角度仰视、俯视或重复的总览机位替代任一方位。
- 左上总览图从主入口或主要叙事轴观察，用于建立空间全貌、入口出口、主要行动路线与叙事区域；右上总览图反向必须将镜头机位与左上总览图镜头机位调换，从原总览镜头对侧沿同一主轴反向观察，完整交代原机位背后的空间、入口出口、行动路线和关键区域，不得做水平镜像；左下左侧面视角从左上总览图主轴向左旋转约 90 度观察；右下右侧面视角从左上总览图主轴向右旋转约 90 度观察。左右侧面共同确认两侧墙面、横向层次、门窗和家具关系。
- 左上总览图是空间连续性的母版。其建筑结构、门窗数量与位置、固定家具、关键陈设、道路或地面关系、物体样式、位置、朝向与摆放角度、材质、昼夜、天气、主辅光方向和事件状态必须被其余三格严格继承。四个方位采用接近水平的观察高度和一致的空间尺度逻辑；允许因机位与遮挡导致元素不可见，但不得随意新增、删除、换色、旋转、镜像或移动固定元素。
- 四宫格可以使用细窄中性分隔线，但不得使用装饰边框、大标题、编号、水印或额外说明文字。除非人物是尺度或剧情所必需，否则不加入可识别角色。
- 若模型输出的整体画幅或格线不精确，允许在不重绘内容的前提下确定性裁切与重排为 1600×900 或更高的 16:9 画布；四格边界必须位于画布水平与垂直中线，使每格为 800×450 或等比例尺寸。
- 用户另有画幅或交付规范时，人物设定板仍优先遵守上述硬性规范，其他类别遵守用户规范。

## 生成与质检

1. 先锁定全局视觉圣经、人物连续性锚点和跨元素关系，再调用可用的图像生成能力逐项生成。优先按人物、关键物料、关键场景的顺序制作；数量过大时按优先级分批。
2. 使用稳定文件名：`类别序号_标准中文名_变体`。人物装造文件使用 `CHR-001_人物名_装造名`，并保存装造变体 ID、适用场次、提示词与图片之间的一一对应关系。
3. 每张图生成后进行视觉检查，而非仅确认文件存在。检查剧情符合度、风格一致性、构图、文字、视图数量、人物身份一致性、时代错误、多余元素和肢体结构。人物换装图还要与基础定妆逐项比较身份锚点，并核对其服装是否覆盖连续性表中的全部适用场次。场景图还要检查四格数量与顺序、单格 16:9、反向总览是否真正调换机位而非镜像、左右侧面是否分别从主轴向左和向右旋转约 90 度、是否误用低角度仰视或重复机位，以及门窗、固定陈设、物体样式、位置、朝向与摆放角度、材质、光线和叙事痕迹能否严格继承左上总览图。
4. 对不合格项定向重试，只修改失败维度；最多尝试三轮。三轮后仍失败则保留最佳版本，并明确列出未满足项，不得声称完全通过。
5. 每次接收并分析一份新剧本、新增集数或修订版剧本，都必须同时输出或更新项目对应的 `resource_registry.xlsx`。即使本轮只要求识别新增资产，也要生成该表；只有用户明确要求本轮不输出文件时才可暂缓，并在结果中说明。若用户提供已有资源登记表，先读取并保留其工作表名、列顺序、格式、既有行、编号和对象路径规则，只追加去重后的新增资产，不覆盖已确认内容。
6. `resource_registry.xlsx` 的工作表默认命名为 `resource_registry`，列名和顺序固定为：`project_id | resource_id | resource_type | name | aliases | object_key | description | always_include | priority | enabled | version`。每个最终需要生成或已生成的资源占一行；人物装造或状态图按独立的 `character` 资源行登记，名称使用“人物名·装造名/状态名”，确保登记行、提示词和图片一一对应。
7. 登记表编号使用项目既有规则；没有旧表时使用 `CHA_001`、`PRO_001`、`LOC_001` 并按类别分别递增。`resource_type` 只使用 `character`、`prop`、`location`；`aliases` 使用 `|` 分隔；`object_key` 使用 `[项目资源前缀/]resources/characters|props|locations/资源ID.png`，若用户或旧表给出资源前缀则必须原样继承，未给出时从 `resources/...` 开始。`always_include`、`enabled` 沿用旧表的数据表达；新表默认分别为 `false`、`true`，`priority` 默认 `10`，`version` 默认 `v1`。人物 `description` 优先复用已确认登记表中的简短外貌概括，避免加入神态、身份、剧情动作或会削弱参考图约束的赘述。
8. 生成完成后输出资产总表、`resource_registry.xlsx`、人物装造连续性表、视觉圣经、逐项提示词、图片或图片路径、质检结果及假设清单。若交付文件，使用清晰目录分开 `characters`、`props`、`locations` 和清单文件；人物基础定妆与换装图放在同一人物目录或使用可排序文件名。交付前检查登记表列名与顺序、编号唯一性、对象路径、去重结果以及表格可正常打开。

## 完成标准

只有在以下条件全部满足时才宣布完成：剧本与风格已读取；三类元素已提取、去重并具备剧情证据；全部必要换装已建立连续性表并具有触发场次；每个纳入范围的元素及装造变体都有提示词和对应图片；所有人物图符合固定白底 16:9 四视图版式；所有场景图符合固定 16:9 四宫格且每格为 16:9；人物跨装造身份一致、场景跨角度空间一致；对应的 `resource_registry.xlsx` 已按固定 11 列生成或增量更新，并通过编号、路径、去重和可打开性检查；关键连续性已检查；失败项和推断均已透明标注。
